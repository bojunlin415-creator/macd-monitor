# MVP 範圍與技術架構

規格 Q20 要求第一階段完成全部核心能力；內部依規格第 14 章交付順序分批實作，以下為批次劃分與目前進度。

## 已定案（2026-11-04）

- 「金叉（未達候選）」CROSS 等級為「觀察」、方向偏多。
- 不提供系統勿擾時段，LINE 一律立即發送；通知設定頁提示使用手機勿擾模式。

## 技術架構（工程預設，規格 3.1 允許「團隊最熟的單一語言」）

- 後端：Python 3.12+、FastAPI、SQLAlchemy 2；正式 PostgreSQL，開發／測試 SQLite。
- 計算：同一個 Python 程式庫（`app/engine`），純函式、可離線重現，避免跨語言數值差異。
- 工作者：`app/workers/runner.py` 常駐排程（各市場收盤後 30 分鐘、週六 12:00 摘要），工作鍵 market|date|type|version 防重入。
- 事件與待送佇列同一交易寫入；LINE 投遞在交易外，沿用 X-Line-Retry-Key 重試。
- 前端：React + Vite + TypeScript，全繁中，淺色／深色主題、紅漲綠跌可切換。

## 尚待使用者決定

- 行情供應商與授權（X-02、X-03）：目前用虛構代號示意資料（T001、U001、J001…），不是真實行情。
- 雲端商與部署方式（X-05）。
- LINE 官方帳號（Messaging API channel）的 token／secret／Basic ID。

## 與規格的差異／簡化

- LINE 綁定：使用者把網站產生的一次性綁定碼（10 分鐘）傳給官方帳號，由簽章驗證過的 Webhook 取得 userId；不接受手動輸入 LINE ID。
- CSV 預覽暫存在 API 程序記憶體（15 分鐘），多程序部署時需改存資料表或 Redis。
- 交易日曆目前為「週一至週五扣除休市日」，休市與提早收盤資料需由正式供應商提供。
